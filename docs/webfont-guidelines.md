# Webフォント利用ガイドライン

## 目的

Webフォントの導入または更新による転送量の増加を抑え、Lighthouseの計測値を悪化させないことを目的とする。

このガイドラインは、フォントの追加、置換、バージョン更新、サブセットと読み込み範囲の変更に適用する。

## 受け入れ基準

影響を受ける代表ページをコールドキャッシュで計測し、原則として次の条件をすべて満たす。

- 実際に読み込まれるフォントのページ単位の合計転送量は、数十KiB以内を目標とする。
- 合計転送量が数百KiBに達する場合は、OS標準フォントでの代替、サブセット、読み込み範囲を再検討する。
- フォントのリクエスト数を最小限に抑え、各ファイルがそのページに必要であることを確認する。
- 同じ設定で実行したLighthouseの3回の中央値を比較し、Performance、FCP、LCP、CLSを悪化させない。
- リポジトリのLighthouse警告基準をすべて満たす。

数百KiBの配信が必要な場合は、必要な表現、変更前後の転送量、代替案、Lighthouseの比較結果をプルリクエストに記録する。
そのうえで、表現上の必要性が性能上の不利益を上回ると判断できる場合に限り受け入れる。

## フォントの選定

- OS標準フォントで要件を満たせる場合は、Webフォントを追加しない。
- 日本語を含むCJKフォントは字形数が多いため、OS標準フォントを第一候補とする。
- 同じ用途を担えるフォントがある場合は、別のフォントを追加しない。
- 利用するウェイト、スタイル、文字集合、OpenType機能、可変軸を導入前に列挙する。
- Variable FontとStatic Fontは、実際に配信するファイルの合計サイズで選ぶ。

## 配信ファイルの作成

- ブラウザー向けの新規フォントはWOFF2で配信する。
- 必要な文字集合だけをサブセット化し、`unicode-range`でブラウザーが不要なファイルを読み込まないようにする。
- 使わないウェイト、スタイル、可変軸の範囲、文字、OpenType機能を含めない。
- 必要なOpenType機能とその代替字形は、サブセット後のフォントに残っていることを実際のテキストで確認する。
- 可変軸の値を固定できる場合は、固定した後のサイズを比較する。

## 読み込み範囲

- 全ページで使わないフォントはグローバルに読み込まない。
- 特定のページまたはコンポーネントだけで使うフォントは、その範囲でだけ読み込む。
- `preload`は、初期表示範囲のテキストに必要で、計測によってFCPまたはLCPの改善を確認できたフォントに限る。
- `font-display: swap`を基本とし、フォントの取得がテキスト表示を妨げないようにする。
- フォールバック時と読み込み後のレイアウト差を確認し、CLSを悪化させない。

## 導入と更新の手順

1. 変更対象の代表ページで、フォントのリクエスト数、合計転送量、Lighthouseの3回の中央値を記録する。
2. 必要な文字集合、OpenType機能、ウェイト、スタイル、可変軸だけを残したWOFF2を作成する。
3. 本番ビルドで、想定したファイルだけが読み込まれ、必要な文字と字形が表示されることを確認する。
4. 変更後も同じ条件で計測し、受け入れ基準と比較する。

プルリクエストには、少なくとも次の比較を記載する。

| 指標                   | 変更前 | 変更後 |
| ---------------------- | -----: | -----: |
| フォントのリクエスト数 |        |        |
| フォントの合計転送量   |        |        |
| Lighthouse Performance |        |        |
| FCP                    |        |        |
| LCP                    |        |        |
| CLS                    |        |        |
